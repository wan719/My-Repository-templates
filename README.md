# My-Repository-templates

用于保存可复用的仓库初始化模板。当前提供前后端目录入口，以及面向开发者与 AI Agent 的开发和测试约定。

## 目录

```text
backend/   后端工程入口（尚未初始化应用）
frontend/  前端工程入口（尚未初始化应用）
doc/       开发、Git 协作与测试规范
```

## 当前模板

- [软件测试规范](doc/test.md)：说明测试职责、按风险选择测试的方法、执行时机、质量门禁和 Agent 报告要求。
- [后端技术栈与开发约定](doc/backend.md)：Java/Spring 业务后端的结构与开发参考。
- [前端技术框架](doc/frontend.md)：Vue H5 与 Web 管理端的技术选型和职责参考。
- [Git 协作与提交约定](doc/git.md)：日常同步、提交信息及冲突处理。
- [Agent 项目规则](AGENTS.md)：要求涉及代码和测试的任务先阅读测试规范，并报告实际验证结果。

## 新项目初始化清单

从本模板创建新仓库后，按实际项目逐项完成：

- [ ] 修改仓库名称、README 中的项目介绍及文档中的项目专属信息。
- [ ] 确定是否需要后端、H5、Web；只初始化需要的工程，并替换 `backend/`、`frontend/` 中的目录说明。
- [ ] 确定后端包名、业务模块与数据库初始化方式，更新 [后端约定](doc/backend.md)。
- [ ] 确定前端页面、接口对接方式及是否同时建立 `frontend/h5/` 和 `frontend/web/`，更新 [前端约定](doc/frontend.md)。
- [ ] 验证并记录 JDK、Node.js、框架及依赖版本；提交构建文件、包装器或锁文件。
- [ ] 提供不含真实凭据的环境变量示例，确认本地密钥和构建产物被忽略。
- [ ] 在 README 中写明实际安装、启动、构建和测试命令；更新 [测试规范](doc/test.md) 中的工具、测试目录与运行命令。
- [ ] 明确核心业务验收条件，配置与项目匹配的 CI 检查及合并门禁，并记录实际执行证据。

这些文档是初始化参考，不表示本仓库已有可运行工程。具体项目应在完成工程初始化后维护相应文档。
